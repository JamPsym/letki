Native Letki music engine — verified baseline, 2026-10-17
======================================================

C++17 implementation: host/player/.
Guide: host/player/README.txt. Word tools: docs/player-word-tools.txt.
Build: make player. Tests: make player-test; make player-sanitize.
The default MCU firmware build and the R3 milestone are preserved.
No application flash, option-byte, programmer power or CAD changes occurred.

The engine plays local audio through PortAudio with absolute DAC presentation
clock scheduling. It streams from a fixed512KiB ring, analyzes24logarithmic FFT
bands at50Hz, detects separate bass/treble attacks and supports title text,
held/scrolling word cues, seek/pause, full0..100 LEVEL8 PWM or GRAY4, simulated
five-node firmware, explicit physical UART, baud recovery, bounded future frames
and persistent-show retention. The default is LEVEL8 at12fps/230400baud, with
My Cyganie as the selected local preset. No Python runtime is used by playback.

The current art direction uses the original silk ribbon and ripple garden
geometry, with bass-hit motion bursts, strong PWM pulses and small treble highlights.
Video now plays in full color on the PC above the simulator. It never affects
LED pixels. V toggles that PC panel; N advances instrument/effect cues. Earlier
video-to-LED texture experiments were a misunderstanding and have been removed.
The user permits repeated shapes and asks for clear ideas. The instrument theatre
prototype uses piano keys, organ pipes, mallets, guitars, mandolin and hanging
bells. Its announcement labels/timings are explicitly draft. Original PWM
geometry/music is available unobstructed in config/player/original-pwm.json.
The user especially likes its first two scenes: music-ribbon/music-ripple retain
those shapes while bass attacks move/brighten them and treble lights their cores.
The first music-reactive tuning was rejected as perceptually ineffective despite
valid UART traffic. A revised envelope uses a55ms hold,85ms release,2.5% floor,
full attack gain and a seven-step motion burst per bass event. This is a creative
prototype; packet/render tests alone do not establish musical quality.
config/player/my-cyganie-shapes.json alternates these every20seconds.

Limitations: optical timing/skew, electrical waveforms/current/rails and runtime
MCU stack high-water were not measured. The existing R3 hardware qualification
limits remain. Audio synchronization relies on the selected backend's DAC clock;
UART midpoint offsets include chain asymmetry. Source/video cache and telemetry
are bounded. Independent board-clock changes are detected periodically; already
queued frames can be affected until detection. Saved-show restoration needs fresh
shared I2C clocks, and reports failure if those are stale. Abrupt SIGKILL cannot
run cleanup. The game/animation art direction is subjective and remains editable.
